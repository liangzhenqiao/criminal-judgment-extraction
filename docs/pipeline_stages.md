# Pipeline stages: scripts in run order

All paths are read from `config.yaml` (keys in `config.example.yaml`).
"Work" means `<work_dir>`; intermediate tables keep the run timestamps that the
production run gave them, so each script finds its predecessor's file by name.

## 01_preprocess — filter, segment, pre-fill

| Script | Input | Output |
|---|---|---|
| `01_stream_zip_to_parquet.py` | one yearly zip archive (`--zip`) | hive parquet of documents passing the production filter: case-type code 4, procedure first instance / second instance / retrial, parseable judgment date |
| `02_segment_paragraphs.py` | output of 01 | four passages per judgment: defendant information, fact finding, operative judgment, signature block |
| `03_regex_prefill.py` | output of 02 | fifteen regex hint fields (`sex`, `birth_year`, `age_at_case`, `edu_level`, `prior_occupation_raw`, `hukou_text`, `sentence_type`, `sentence_months`, `fine_yuan`, four sentencing-circumstance flags, `judge_chief`, `judge_members`) |
| `04_build_residual_batches_2014_2021.py` | output of 03 | 21-key input batches for 2014–2021 (`--build-batches-only`; the request path to a local Fabric server is the earlier prototype) |
| `05_build_llm_batches_1985_2013.py` | output of 03 | 21-key input batches for the 1985–2013 supplement (every case, global id de-duplication) |
| `06_extract_offense_dates_regex.py` | facts-only pack (`--pack`) | guarded full-date regex for offense dates plus procedural dates |
| `07_offense_date_front.py` | segmented passages | facts-only pack → 06 → residual batches for the 7-key task |
| `run_all_preprocess.sh` | `corpus_zip_dir`, `admin_division_json` | runs 01, 02, 03, 05, 07 for a set of years |

## 02_extraction — contract-bound model extraction

| Path | Role |
|---|---|
| `profiles/tasks/criminal_defendant_v1.3/` | 21-key main instruction set: `pattern.md` (system prompt, sent as-is, snapshot header included), `schema.json`, `acceptance.yaml`, `grounding.py`, `verdict.spec.md`. The copy deposited with the data is this prompt with the snapshot header removed. `release_output_schema.json` is the schema copy deposited with the data |
| `profiles/tasks/offense_date_v1.0/` | 7-key offense-time instruction set and its runner |
| `profiles/tasks/offense_name_v1.0/` | 5-key offense-name instruction set and its runner (generated by `03_merge_release/08_build_offense_name_profile.py`) |
| `profiles/models/`, `profiles/runtime/`, `profiles/litellm/` | pinned model, serving and gateway parameters |
| `runner/run_full_extraction.py` | batch runner for the 21-key task: bounded concurrency, acceptance checks (record count, schema, prior-array alignment), failure ledger, resumable state |
| `scripts/` | gates: environment doctor, artifact check, vLLM and LiteLLM launch, smoke stages A and C, smoke verdict, grounding comparison |

## 04_validation

| Script | Purpose |
|---|---|
| `01_structural_constraints.py` | the nine structural and logical constraints (C1–C9) on the full release |
| `02_corpus_single_pass_scan.py`, `03_corpus_scan_summarize.py` | one streaming pass over the archive: per-year counts at each filter layer, defendants named per judgment, case number → source URL |
| `04_regex_privacy_scan.py` | regex scan of released free-text fields for ID numbers, phones, addresses and names (candidate values stay local) |
| `02_extraction/scripts/g3_stage3.py` | model-based second review of the values the regex scan flags as address-like: house-number vs compound vs administrative area, so the in-text address residue can be counted rather than guessed |
| `05_build_judge_id.py` | replaces `judge_name` by an HMAC-based `judge_id` (dry run by default; the secret and the mapping are never written into the release) |
| `annotation/01_draw_audit_sample.py` (validation bundle) | stratified sample of released records and of corpus criminal judgments for human validation |
| `annotation/02_draw_hard_cases.py` (validation bundle) | hard-case sample (multi-defendant judgments, two or more prior convictions) |
| `annotation/03_build_pack.py` (validation bundle) | annotation cards and workbooks |
| `annotation/04_score_annotations.py` (validation bundle) | agreement (κ, AC1, α), adjudication list, field-level precision/recall/F1 with intervals |
| `check_public_release.py` | leak gate for this repository |
| `tests/` | judge_id, pattern copy and gate tests |

The scale ratio of released records to official criminal case intake (by
year) was computed by hand from published yearbook tables; no script exists.
